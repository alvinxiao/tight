# Windows installer preview

The Windows CI artifact includes `installer/TIGHT-<version>-windows-x64-preview-setup.exe` alongside the portable app folder. The installer contains Electron, the backend, and the browser assets. It does not download a runtime or require Node or Git on the player's PC.

1. Download `TIGHT-windows-x64-preview` from a successful Actions run and extract it.
2. Open the preview setup executable in its `installer` folder.
3. Complete setup, then open **TIGHT** from the Start menu.
4. Create a game and use **Wi-Fi sharing** to invite phones on the same private network.

This preview is unsigned. Windows may display a publisher or reputation warning. Use only the artifact from the intended repository and successful run. The preview is for evaluation and does not authorize public distribution of the bundled game material.

The installer targets Windows x64 and installs for the current user under `%LOCALAPPDATA%\Programs\TIGHT`. It requests no administrator elevation. Windows 11 x64 is the qualification target; clean standard-user machines remain to be tested in #26. ARM64 is not supported by this build.

Remove the app from **Settings > Apps > Installed apps**, or run **Uninstall TIGHT.exe** in its install folder. Uninstall removes the Start menu shortcut and application files. It preserves saved games in `%LOCALAPPDATA%\TIGHT` and the per-user Chromium profile. Reinstalling uses those existing games. Export important games before changing versions. Close TIGHT before installing or removing it; do not interrupt a live game to update.

## Build and verify

Run `npm ci --legacy-peer-deps` on Windows, then `npm run installer:windows:preview`. The command builds the existing self-contained app, then runs electron-builder's NSIS target against that packaged directory. `scripts/windows-installer-config.mjs` owns the app identity, per-user install policy, and artifact names. The packager and installer share `org.alvinxiao.tight` and `TIGHT.exe`. The original blue T icon is generated by `node scripts/create-desktop-icon.mjs` and contains no third-party artwork.

Windows CI runs the actual preview installer silently. It checks the Start menu target, per-user uninstall registration, application license and third-party notices, then launches the installed app to create a save in the default data directory. It uninstalls, reinstalls, launches again, and compares the complete exported save before a final uninstall. The runner must have no existing TIGHT installation or saved games. This check does not replace clean standard-user, SmartScreen, or physical phone testing.

The package retains Electron's `LICENSE`, Chromium's `LICENSES.chromium.html`, the repository's original MIT notice as `TIGHT-LICENSE.txt`, and `THIRD-PARTY-NOTICES.txt`. These notices are also available for review in the portable directory. Dependency notices do not resolve the separate rights to redistribute Twilight Imperium names, rules text, or artwork.

## Signed releases

`npm run installer:windows:release` is separate from preview packaging. It fails before building the installer unless the release environment supplies all of these values:

- `CSC_LINK` is the absolute path of the publisher's PFX certificate mounted by the release secret store.
- `CSC_KEY_PASSWORD` supplies its password through the release secret store.
- `TIGHT_RIGHTS_REVIEW_URL` points to the completed distribution-rights review over HTTPS.

A URL is a recorded review reference, not an automated legal decision. The release operator must check that review and the publisher credentials. Never commit certificates, passwords, or fabricated review approvals. The packager signs the app binaries, then electron-builder signs the installer and uninstaller. Mandatory signature checks reject a release when signing fails; signing alone does not guarantee Windows will suppress reputation prompts. Preview packaging rejects supplied signing credentials and explicitly disables executable signing.

No signing secrets, completed rights review, public release workflow, or automatic updater are supplied by this change. #23 remains open for signed distribution and installer qualification. #24 remains open for verified upgrade behavior, failed-update recovery, and offline qualification. Builds never publish artifacts automatically; CI uploads only the unsigned evaluation artifact.
